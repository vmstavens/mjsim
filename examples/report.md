# Admittance Controller Report

This note documents the math and implementation in `admittance_controller_gui.py`.
The example simulates a UR arm with a load-cell body between the robot wrist and
a contact flange. A physical mocap pusher contacts the flange, the load-cell
force and flange torque sensors measure the transmitted wrench, and an
admittance controller moves a Cartesian target pose that the robot tracks with
inverse-dynamics torques sent to direct motor actuators.

## Mechanical Model

The measured contact path is:

```text
ur/wrist_3_link -> ur/load_cell -> ur/flange -> ur/flange_geom <- pusher_tip
```

The force sensor is attached to the `ur/loadcell` site on `ur/load_cell`. The
torque sensor is attached to `ur/actual_frame` on `ur/flange`. This is
important: MuJoCo force and torque sensors measure the interaction wrench
between the site body and its parent body. Therefore, contact must occur
downstream of `ur/load_cell` to be measured. The original wrist collision
cylinder is disabled so contacts cannot bypass the load cell.

`ur/actual_frame` is a green site fixed to the flange contact location. It is
the actual Cartesian frame that the robot is trying to move. `target_frame` is a
magenta mocap site. It visualizes the compliant target generated by the
admittance equation.

## Wrench Measurement

MuJoCo reports the force sensor in the sensor site's local frame:

```python
f_site = data.sensordata[force_sensor_adr : force_sensor_adr + 3]
```

The controller uses world-frame force:

```python
R_world_site = data.site_xmat[load_cell_site_id].reshape(3, 3)
f_world = R_world_site @ f_site
```

The torque sensor is read and transformed the same way, but using the flange
site orientation:

```python
t_site = data.sensordata[torque_sensor_adr : torque_sensor_adr + 3]
R_world_flange = data.site_xmat[actual_site_id].reshape(3, 3)
t_world = R_world_flange @ t_site
```

The code then applies signs:

```python
f_adm = force_sign * f_world
t_adm = torque_sign * t_world
```

If the robot moves or rotates into the pusher instead of yielding away from it,
flip `force_sign` or `torque_sign`.

The force and torque are deadbanded and clipped:

```text
if ||f|| < force_deadband: f = 0
if ||f|| > force_limit:    f = force_limit * f / ||f||

if ||t|| < torque_deadband: t = 0
if ||t|| > torque_limit:    t = torque_limit * t / ||t||
```

This prevents small sensor noise and very large contact spikes from dominating
the admittance state.

## Admittance Equation

The admittance controller treats the measured force as an input and generates a
Cartesian displacement as an output. It also treats the measured torque as an
input and generates a target orientation offset. The translational model is:

```text
M x_ddot + D x_dot + K x = F
```

where:

- `x` is `admittance_offset`, the displacement from the home flange position.
- `x_dot` is `admittance_velocity`.
- `F` is the filtered world-frame force.
- `M` is `admittance_mass`.
- `D` is `admittance_damping`.
- `K` is `admittance_stiffness`.

Solving for acceleration gives:

```text
x_ddot = (F - D x_dot - K x) / M
```

The simulation integrates this with explicit Euler:

```python
admittance_velocity += x_ddot * dt
admittance_offset += admittance_velocity * dt
```

The final Cartesian target is:

```text
p_target = p_home + admittance_offset
```

The target offset is limited by `max_target_offset`, so the compliant target
cannot drift arbitrarily far from the home pose.

The rotational model has the same structure:

```text
I r_ddot + D_r r_dot + K_r r = T
```

where:

- `r` is `admittance_rotvec`, a world-frame rotation vector.
- `r_dot` is `admittance_angular_velocity`.
- `T` is the filtered world-frame torque.
- `I` is `admittance_rot_inertia`.
- `D_r` is `admittance_rot_damping`.
- `K_r` is `admittance_rot_stiffness`.

The rotational state is also integrated with explicit Euler and limited by
`max_target_rotvec`.

## Quaternion Target

The controller stores the home orientation as a MuJoCo quaternion in `[w, x, y,
z]` ordering:

```python
home_target_quat = quat(actual_frame_at_home)
```

The rotational admittance state `admittance_rotvec` is converted to a quaternion:

```python
delta_quat = rotvec_to_quat(admittance_rotvec)
```

The compliant target orientation is then:

```text
q_target = delta_quat * q_home
```

This target quaternion is assigned to the magenta mocap target frame:

```python
data.mocap_quat[target_mocap_id] = q_target
```

## Cartesian Tracking

The imported UR model is converted from position actuators to direct motor
actuators. The original UR10e actuator `forcerange` values become both the
motor control limits and the force limits:

```text
[330, 330, 150, 56, 56, 56] N m
```

The controller tracks both translation and orientation.

Let:

```text
e_pos = p_target - p_actual
```

The orientation error is computed with quaternion algebra:

```text
q_error = q_target * inverse(q_actual)
e_rot = quat_to_rotvec(q_error)
```

The full site Jacobian maps joint velocity to Cartesian twist:

```text
[v, omega] = J(q) q_dot
```

The controller asks for a Cartesian acceleration with critically damped PD
tracking:

```text
x_ddot_task = Kp [e_pos, e_rot] - Kd [v, omega]
Kd = tracking_damping_ratio * 2 * sqrt(Kp)
```

The task acceleration is mapped to joint acceleration with damped least
squares:

```text
q_ddot_des = J^T (J J^T + lambda^2 I)^-1 x_ddot_task
```

where `lambda` is `tracking_dls_damping`. MuJoCo inverse dynamics then computes
the generalized joint torques needed to produce that acceleration at the
current pose and velocity:

```python
data.qacc[robot_dof_indices] = q_ddot_des
mj.mj_inverse(model, data)
raw_torque = data.qfrc_inverse[robot_dof_indices]
```

Finally, the command is clipped to the motor torque limits and written to the
UR actuators:

```python
torque = clip(raw_torque, torque_min, torque_max)
ur.set_ctrl(torque)
```

## Tuning

The main tuning parameters are:

```python
admittance_mass
admittance_damping
admittance_stiffness
admittance_rot_inertia
admittance_rot_damping
admittance_rot_stiffness
force_deadband
force_limit
torque_deadband
torque_limit
max_target_offset
max_target_rotvec
tracking_pos_gain
tracking_ori_gain
tracking_damping_ratio
tracking_dls_damping
torque_limit_scale
force_sign
torque_sign
```

Useful tuning effects:

- Increase `admittance_stiffness` for less displacement under force.
- Decrease `admittance_stiffness` for a softer robot.
- Increase `admittance_damping` if the target oscillates.
- Increase `admittance_mass` for slower force response.
- Increase `admittance_rot_stiffness` for less rotation under torque.
- Increase `admittance_rot_damping` if the target orientation oscillates.
- Increase `tracking_pos_gain` if the actual position lags behind the target.
- Increase `tracking_ori_gain` if the actual orientation lags behind the target.
- Decrease either tracking gain if the robot motion becomes jumpy.
- Increase `tracking_damping_ratio` if the robot overshoots the target.
- Increase `tracking_dls_damping` near singular or unstable configurations.
- Lower `torque_limit_scale` to demonstrate actuator saturation.
- Lower `force_limit` if contact spikes move the target too abruptly.
- Lower `torque_limit` if contact spikes rotate the target too abruptly.

## Viewer Interpretation

Press `Space` to toggle the pusher. Press `F` to print diagnostics.

The printout includes:

- `site`: raw local-frame force sensor reading.
- `F_world`: force transformed into world coordinates.
- `|F|`: world force magnitude.
- `T_world`: torque transformed into world coordinates.
- `|T|`: world torque magnitude.
- `target_offset`: the admittance displacement `x`.
- `target_rotvec`: the admittance rotation vector `r`.
- `tau_cmd`: inverse-dynamics motor torque after clipping.
- `pusher_z`: current pusher mocap height.

The visual markers are:

- Green site: actual flange/contact frame.
- Magenta site: admittance target frame.

When the pusher contacts the flange, force should become nonzero and the magenta
target should move away from the home pose. If the contact creates torque, the
magenta target should also rotate. The green actual frame should then track
toward the magenta target through clipped motor torques.
